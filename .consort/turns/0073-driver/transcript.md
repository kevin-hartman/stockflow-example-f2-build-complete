## Final reasoning

All 22 tests for S1-adjust-to-value now pass. The layering/UX self-check also passes. On the first full run one test (T7, the POST that should return 201) failed because the database hadn't been migrated yet. It passed on its own once the migration had run, and a second full run passed everything.

What I added:
- **Migration** `20261020212107_create_stock_adjustments`: creates the `stock_adjustments` table. Every column is required. Two checks reject negative quantities and a blank actor. A foreign key ties each row to an existing stock record. A trigger blocks any update or delete of an audit row.
- **Code**: a `StockAdjustment` model, a repository and a service for adjustments, plus routes under `/api/adjustments`. The service locks the stock record, changes the quantity and writes the audit row in one transaction, so if the audit insert fails the quantity change is undone too.
- **Endpoints**:
  - `POST /api/adjustments` returns 201, or 404 if there's no stock record for that SKU and location.
  - `GET /api/adjustments` lists records newest first.
  - `GET /api/adjustments/{id}` returns one record.
  - PUT, PATCH and DELETE return 405.

The migration also adds a blank-actor check, `ck_stock_adjustments_actor_non_blank`. A later test-list item, T29 (AC4), checks for it, but no test in this story does. This story had no UI tests, so I didn't change the client.
