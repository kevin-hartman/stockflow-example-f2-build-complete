## Final reasoning

I annotated all four S1-adjust-to-value ACs and wrote `architecture.json` and `architecture.md` for F2. The self-check passes; the first run failed because the NFRs had a clause list but no single summary test line, so I added one to each.

**Layers:**
- **AC1 (form sets the corrected level):** E2E, against the new `POST /api/adjustments`.
- **AC2 (audit record captures when and who):** API.
- **AC3 (audit record can't be changed):** API. There are no edit/delete routes, and a database trigger also rejects direct changes.
- **AC4 (actor required):** E2E. The server's 422 for an empty actor shows as the inline `field-actor-error`. The actor is a name the operator types, since V1 has no login.

All four use the F1 module layout, unchanged.

**Data design:**
- A new table, `stock_adjustments`, holds the audit records and only ever gets new rows. It is written in the same transaction as the stock quantity update.
- Persistence invariants PI8–PI15 cover the required columns, a non-blank actor, no negative quantities, the link to `stock_records`, the no-change trigger, the atomic write, and both migration checks. One migration check covers recreating the new table; the other confirms existing stock rows survive the migration.
- AP3 tells the database designer about a new lookup: audit records for one SKU and location, newest first.

**Requirements from `nfrs.md`:** R1–R5 are all covered, with each check tied to the AC it belongs to. The pick-overcommit half of R2 doesn't apply to adjustments and stays with the pick feature.

**Decision for you at the design gate:** the adjust form's Location dropdown should list every location that has a record for the chosen SKU, including empty ones, and no current endpoint returns exactly that. I recommend reusing the existing all-locations list and showing a form error if the chosen pair has no record, rather than adding an endpoint. No S1 AC depends on this.

**One thing to fix in `architecture.md`:** a sentence in the Test strategy section about cleaning up audit rows came out muddled. The intended rule: since audit rows can't be deleted, tests can't clean them up, so each test should use its own unique SKU values.
