## Final reasoning

I wrote all 22 RED tests to `tests/test_stock_adjustments.py`. I ran only the first with `-x`, and it fails as expected (no `/api/adjustments` route yet). I did not run the other 21 or the self-check.

- **Test style:** I used plain pytest rather than Gherkin for the behavior items. They have no `scenario_file`, and the existing tests in this repo are plain pytest. I did not write any `.feature` or step-def files.
- **Guessed names:** the tests assume `AdjustmentService` in `app/services/adjustments.py`. They also assume the `stock_adjustments` columns `sku`, `location`, `prior_quantity`, `new_quantity`, `actor` and `adjusted_at`. The 405 tests expect `GET /api/adjustments/{id}` to return the record.
- **T20 (forced audit failure):** it provokes the failure with a 100,000-character actor instead of patching a repository function. That only fails if the `actor` column has a length limit, so it would pass wrongly if the Driver makes it unbounded text.
- **T12–T14 and T24–T26:** each group is one parametrized test with the id marker added at runtime. The per-test dashboard signal may not pick those markers up.
